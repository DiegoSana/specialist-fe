# i18n (next-intl)

- Locales are `['es', 'en']` (`i18n.ts`), default `es`. Every route lives under `app/[locale]/...`.
  Page/layout components receive `params: Promise<{ locale: string }>` (Next 16 async params) —
  `const { locale } = await params;`, don't destructure synchronously.
- Translation namespaces are the top-level keys of `messages/es.json` / `messages/en.json`
  (`common`, `auth`, `dashboard`, `client`, `specialist`, `professionals`, `navigation`, `profile`,
  `home`, `components`, `footer`, `company`, `notifications`, `profileSetup`, `profileActive`,
  `verification`, ...). Add new pages/features under an existing namespace when the content
  belongs there, or add a new top-level namespace for a genuinely new feature area.
- Server Components/pages: `const t = await getTranslations('namespace')` from
  `next-intl/server`. Client Components: `const t = useTranslations('namespace')` from
  `next-intl`.
- **Every new or changed user-facing string must be added to both `messages/es.json` and
  `messages/en.json` with the same key path** — `es` is authoritative (write it first), but a key
  present only in one file will throw or silently fall back at runtime for the other locale.
  Keep nesting/ordering roughly parallel between the two files to make diffs reviewable.
- Don't hardcode Spanish (or English) copy directly in JSX outside of genuinely locale-independent
  strings (brand name, numeric formatting handled by `date-fns`/`Intl`). If you see hardcoded copy
  while touching a file, it's fine to leave it unless the task is specifically about that string —
  don't scope-creep an unrelated i18n cleanup into an unrelated change.
